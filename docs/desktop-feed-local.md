# 桌面动态适配记录

日期：2026-10-23。基础版本：nanoMuse 1.0.5，提交 `18edeb6a`。个人分支：`codex/personal`。本次只修改桌面插件，沿用 nanoMuse 的动态、讨论和本地存储，没有引入新的依赖。

## 已适配的行为

- 四页会话开关：目标、点子、资源库和动态共用左上角布局，按钮距页面左侧 16px、顶部 12px，展开左侧会话、再次点击收起并保留当前页面。主侧栏默认宽度为 78px，分栏比例按该宽度计算。
- 其他页面图标：设置、目标、资源库、设备、聊天工具栏等页面的公共图标入口已接入共用库，点子列表及详情也使用同系列图标。按场景统一工具按钮、导航行和菜单的尺寸、文字间距与颜色继承；保留加载动画、喜欢填充、方向箭头和权限标识。
- 共用图标库：指定目录的全部 76 个 PNG 已原样纳入 `harness/dsh-nanomuse/assets/`，统一添加 `icons-legacy-` 文件名前缀。侧栏改为引用共用资源，其他页面可直接使用现有静态资源路由；位置和用法见 [图标库说明](../harness/dsh-nanomuse/assets/ICONS.md)。
- 侧栏图标：顺序为聊天、搜索、目标、点子、资源库、动态；聊天、搜索、灯泡和报纸使用用户提供的本地图标库，通过透明遮罩适配明暗主题。目标保持圆角勾选框，资源库改为菱形、三角形、圆形和方形。按钮点击区域为 44px、圆形选中底座，间隔 10px、中心间距 54px，图标按实际轮廓采用 22 至 26px。
- 侧栏位置：聊天、搜索、动态等功能 tab 与最近文档组成中间区，在顶部头像和底部菜单之间垂直居中；矮窗口允许中间区滚动，顶部与底部入口不被挤走。
- 会话开关：固定在动态区域左上角，点击后左侧显示当前会话，动态保留在右侧；再次点击收起会话、恢复完整动态。展开和收起期间不新建或删除会话，按钮提示与展开状态同步更新。
- 配图：优先加载动态已经保存的真实图片；没有可用图片时，从原文的 Open Graph、Twitter 图片元数据或正文图片中提取。临近视口才加载，成功前不占位置，失败后隐藏。图片可点击打开对应原文，不使用随机占位图。
- 来源跳转：正文内的高亮链接和标题直接打开原文；不再重复显示来源栏。没有内联链接时，只尝试把正文中已经出现的标题或实体关联到保存的真实来源，不改写文章事实。跳转复用桌面端的外部浏览器桥。
- 创建理由：仅从卡片右上角的更多菜单打开“为何为我创建”；菜单显示动态时间和移除操作，卡片底部保留喜欢和讨论。新批次和 `feed_post` 工具要求保存具体理由，依据实际动态指令、兴趣或目标；讨论时一并传入理由与来源。
- 例行生成：Host 开始调用模型前先保存 `lastTry`，进程在批次完成前退出时，重启后的定时检查遵守两小时重试间隔，不会因当天计划仍到期而立即重复启动。
- 历史兼容：从已有正文链接恢复来源，可尝试补取配图。过去没有保存理由的记录明确提示无法追溯，不根据当前资料编造历史理由。继续兼容原有动态围栏，可读取其中可选的来源、图片和理由字段。
- 喜欢、讨论、继续聊天和移除动态仍使用 nanoMuse 原有流程。

## 源码位置

- `harness/dsh-nanomuse/src/feed.ts`：桌面页面和宿主共用的来源、理由、关键词链接与讨论上下文契约。
- `harness/dsh-nanomuse/src/feed-media.ts`：真实来源页取图、网络边界、并发去重和缓存。
- `harness/dsh-nanomuse/src/rooms.ts`、`rooms-tools.ts`、`fences.ts`：存储、生成约束、工具及历史围栏兼容。
- `harness/dsh-nanomuse/src/client/FeedPanel.tsx`、`rooms.ts`、`styles.ts`、`locales.ts`：桌面卡片、懒加载、弹窗、中英文文案与数据类型。
- `harness/dsh-nanomuse/tests/feed.test.mjs`：新增的动态回归测试。

配图接口只接受已保存的动态编号，沿用房间接口的鉴权与同源检查。取图不携带账号 Cookie，逐次校验重定向并固定经过检查的公网 DNS 地址，拒绝本机与私网目标。限制总时长 12 秒、网页 1 MiB、单图 6 MiB、同时抓取 4 项，缓存最多 64 项或 24 MiB。只返回经过类型检查的 PNG、JPEG、GIF、WebP、AVIF，不转发 HTML 或 SVG。

## 卡片交互调整与重复生成修复

根据手测截图把正文来源链接保持为文本内蓝色高亮可点击样式，移除图片下方重复的来源栏；把创建理由入口收敛到右上角更多菜单，并在菜单顶部显示动态日期。菜单保留理由与移除，卡片底部只保留喜欢与讨论，与参考动态布局一致。已在最新 Web Host 实际页面复验：4 条卡片、3 个正文链接呈蓝色、来源栏为 0、每张卡片底部两个操作；更多菜单显示日期和“为何为我创建”“从动态里移除”，理由弹窗及 Escape 关闭正常。

追查测试后重复生成时发现，`feed/open` 只登记每日计划；已到时的批次由 Host 定时检查触发。开始生成时原先只在内存更新 `lastTry`，若进程中断，下一次启动会丢失两小时失败重试节流并重新调用模型。现已在执行前持久化该时间，并增加模拟中断及重启后的回归检查。

现场状态复核看到动态数为 4、上次成功时间为 2026-10-22 17:48、每日计划为 08:00，检查时 Host 已标记 `feedBusy`。这说明这次真实调用来自已到期的服务端每日计划，而不是 `npm test` 的测试用例；单元测试使用替身 `run`，不会请求模型。刷新页面会调用 `feed/open` 登记计划，但它本身不生成动态。因旧版本未落盘，本次用同样的计划参数保存了正在内存中的 `lastTry`；更新后的 Host 等过首次 90 秒定时检查后，活动任务仍为 0，动态数和成功时间未变，确认没有立刻重跑。

发现并修复两项问题：

1. Web 动态页刷新后返回聊天。现在浏览器用 `#nanomuse-feed` 恢复动态主面板，离开时清除自身标记，保留其他地址片段；Electron 外壳的导航不受影响。已验证刷新保留动态，切回聊天再刷新保持聊天。
2. 首次讨论请求尚未完成时重复点击，可能创建多个会话。服务端按动态编号复用正在创建的请求，不同动态互不阻塞；失败后释放入口，允许重试。新增回归先复现重复创建，再验证修复和已存在会话的复用。

新动态保存的理由、坏图无占位、正文关键词、高亮、喜欢、讨论定位回调和移除使用可刷新的合成数据夹具复验，没有移除真实动态。真实模型生成及回复质量由用户手测确认，自动回归不主动发送测试聊天。

实际 HTTP 验证：房间状态 200、配图 200、无效动态编号 404、未授权图片访问 401、跨来源访问 403。69 个样式钩子及 Host/电脑操作冒烟通过。最新日志为 `build/desktop-feed-web-tests-2026-10-23.log` 和 `build/desktop-feed-web-smoke-2026-10-23.log`，浏览器记录位于 `build/feed-web-check/`。

通过 PowerShell 7 的 `scripts/dev-desktop.ps1 -Web` 启动并加载最新插件。更新服务前等待已有例行工作结束，检查活动任务为零并关闭新工作入口后才重启。当前等待用户手测，没有提交、推送或创建 PR。

来源站点防爬、登录要求、网络限制或没有合适图片时，动态仍可只有正文与来源。历史理由无法无损补全。本轮未调用真实模型重新生成付费动态，生成契约通过模拟批次与真实存储验证。
